# 离线密钥柜

[English](README.md) | **简体中文**

用于生成、分类管理、导入和导出公私钥的本地桌面应用。当前界面为中文。记录保存在本机加密密钥库中，同时提供独立的公私钥文本转文件和公私钥配对校验工具。

应用没有上传、遥测、在线更新或自动下载依赖功能，不启动 Web 服务、不监听端口。原生库和操作系统仍属于信任边界，详见[安全与隐私](#安全与隐私)。

Windows 程序、快捷方式、窗口与 macOS 应用包使用同一套本地生成的应用图标。已经安装的旧版需要更新安装包才能获得新图标。

| Windows 便携包 | 已完成本地构建和实际解压验证；公开标准版不捆绑 PyKCS11，并保留随附依赖许可声明。 |

| 安全保证 | 本地测试与源码复核，不等于独立安全审计或没有任何漏洞的保证。 |

## 功能

- 生成密钥对，在加密库内管理名称、标签和备注。
- 导入受支持的密钥文本或本地文件，识别没有 PEM 头尾的标准 Base64 DER。
- 无需创建或解锁库，即可将公钥或私钥文本转换为文件。
- 导出选中记录对应的私钥；只有公钥的记录不能生成私钥。
- 跨受支持编码比较公私钥是否匹配，校验内容不入库。
- 默认以记录名称作为导出文件名，可分别设置密钥库、密钥导入及导出的默认目录；不覆盖已有文件。
- 加密备份、修改主口令、Ctrl+L 锁定及空闲五分钟自动锁定。
- 可选配置连续失败自毁和双因素口令恢复。

## 算法与格式

支持生成 RSA-2048/3072/4096、ECDSA P-256/P-384/P-521/secp256k1、Ed25519/Ed448、X25519/X448、SM2，以及带加密子密钥的 OpenPGP RSA-3072 主密钥。默认 Ed25519。RSA-1024 仅开放旧公钥导入与转换兼容。

| 格式 | 范围与主要限制 |
| --- | --- |
| PEM / DER | SPKI 公钥、PKCS#8 私钥；支持加密私钥导出。 |
| 无头尾 Base64 DER | 导入/转换受支持的 ASN.1 密钥；它不是独立的密钥算法。 |
| RSA PKCS#1 / EC SEC1 | 相应算法的导入/导出；本工具的私钥导出必须显式允许明文。 |
| OpenSSH | 支持的 RSA、Ed25519、NIST ECDSA 公私钥；加密私钥导出使用 bcrypt。 |
| JWK | 单个 RSA、EC 或 OKP 密钥；私钥导出为明文。不支持 JWKS、对称密钥或远程 JKU/X5U 获取。 |
| PKCS#12 / PFX | 单私钥及附带证书；支持加密导出及仅私钥导出；拒绝多私钥容器。 |
| OpenPGP | 支持的 v4 密钥、身份和子密钥；ASCII / 二进制导出；不是对所有原始签名的逐字节归档。 |
| PuTTY PPK | 支持的密钥使用 v2/v3；v2 仅用于旧系统兼容。 |
| JKS | 私钥及可信证书、独立存储/条目口令、证书保留；属于旧式保护，不支持 JCEKS/BKS。 |
| X.509 与证书集合 | 保留导入证书；导出证书 PEM、PEM 集合或 P7B。不签发证书、不构建信任链、不在线查询吊销。 |
| SSH 证书 | 导入、签名检查和原证书导出；签名正确不代表 CA 受信任。 |
| X25519 raw Base64 / Base64url | 必须显式选择原始 32 字节密钥模式；私钥导出必须允许明文。 |
| 旧式加密容器 | 在资源限制内导入传统 PEM 加密头、支持的 PBES1/3DES 及 scrypt 容器。 |
| PKCS#11 | 显式选择本地驱动、枚举公钥、生成 RSA 密钥及签名检查；不导出设备私钥值。 |

算法与格式并非任意组合都兼容。拒绝未知算法、DSA、RSA-1024 私钥、OpenPGP v5/v6、PPK v1 及超出预算的 KDF 参数。修改扩展名不会转换格式。具体变体及上限见 [COMPATIBILITY.md](COMPATIBILITY.md)。

## 本地运行

### Windows 便携版

如果已有可信的本地构建包 `dist/offline-key-vault-windows-x64.zip`，完整解压到普通本地目录，然后双击 `OfflineKeyVault.exe` 或 `launch.cmd`。目标电脑无需安装 Python、pip 或取得管理员权限。启动器使用 Windows .NET Framework 4.x。

不要在 ZIP 内启动，也不要把应用、密钥库或导出文件放在网络共享、链接目录或云同步目录。已验证的安装文件见 [GitHub Releases](https://github.com/Yiya-ai/offline-key-vault/releases)。

- `self-test.cmd`：使用临时合成密钥执行离线自检。
- `verify.cmd`：检查包内摘要。摘要可检测变化，不能认证发布者身份。
- 升级时解压新副本，再打开已有 `.okv`；删除旧程序目录前保留其中的库和导出文件。

### 源码启动

准备可信的 Windows x64 CPython 3.12（含 Tk）及 [requirements.txt](requirements.txt) 中的精确版本依赖。先在独立环境准备兼容 wheel，再仅从本地目录安装：

```powershell
python prepare_vendor.py .\wheelhouse
python -I -S launch.py
```

`wheelhouse` 是需要自行准备内容的本地示例目录。`prepare_vendor.py` 使用 pip 的 `--no-index`、`--no-deps` 和仅二进制输入，不会下载缺失包。运行入口禁用自动 site 初始化，并在导入应用模块前安装离线审计钩子。

### 构建 Windows 便携包

本地依赖齐备后运行 `build_portable.cmd`，或：

```powershell
python -I -S build_portable.py
```

构建器复制白名单源码、本机 Python/Tk 运行时、指定依赖及许可说明，不下载、不上传。它会在新的路径实际解压测试包，检查运行时隔离、篡改及缺文件拒绝，通过后才将最终 ZIP 写入 `dist/`。

macOS 15 及以上系统可下载对应 arm64 / x86_64 DMG，打开后将应用拖入“应用程序”，无需另装 Python。本版本**未公证**；首次打开方法、原生构建检查和平台安全边界见 [MACOS.md](MACOS.md)。

## 安装程序与桌面交互更新

Windows 标准安装器在暂存目录创建文件遇到临时拒绝访问或共享冲突时进行有限重试，不截断已有暂存文件，也不重试已部分写入的流；持续拒绝时安全停止。原目录升级通过带恢复记录的重命名操作替换程序组件，不需要关闭杀毒软件或系统防护。已发布版本和验证后的下载文件见 [GitHub Releases](https://github.com/Yiya-ai/offline-key-vault/releases)。

OpenSSH 重新导出会生成新的随机校验数，可能改变 Base64 换行和填充，目前也不会保留原 SSH 注释。这些差异不改变密钥对。需要逐字节一致时请选择 **「导出原文」**；仅选择与导入相同的格式，并不意味着原样保存文件。

安装位置分为“磁盘”和“具体路径”，例如 `D:\` + `Apps\OfflineKeyVault`；粘贴完整本地路径会自动拆分。目录选择窗口采用相同布局，输入后实时更新，路径无效时不能确认。安装窗口按内容调整高度，仅在屏幕可用高度不足时显示滚动条。

Windows 先关闭密钥柜，再双击 `dist/offline-key-vault-setup.exe`，选择原安装目录即可原位升级；存在标准桌面或开始菜单快捷方式时，默认识别其中的安装位置。指向该目录的已有快捷方式会自动更新，包括改过名称的桌面快捷方式；勾选项控制是否创建缺失的标准快捷方式，不覆盖指向其他程序或其他安装目录的同名快捷方式。安装全程离线，仅面向当前用户，不需要管理员权限，不安装系统服务或注册表项目，完成后不会自动启动应用。

升级仅替换程序清单中的组件；存放在 `app`、`runtime`、`licenses` 之外的密钥库、恢复文件和导出文件原位保留，用户目录中的设置文件也不改动。启动器允许程序内部目录之外的数据文件，但仍拒绝额外代码、动态库及程序内部目录中的未列出文件。程序文件被修改、程序内部目录混入个人文件，或选择了其他软件目录时，会安全拒绝覆盖；请先把个人文件移出这些程序内部目录。

程序运行中会拒绝升级，不强制结束进程。升级失败自动回滚；安装器中途退出后，重新运行安装器并选择同一目录，会先恢复旧安装再重试。旧程序组件保留在安装目录旁的 `.offline-key-vault-upgrade-*` 目录，备份不复制个人数据，确认新版正常后再自行处理。这是离线安装包升级，不是联网自动更新。手动删除安装目录前，应先移出自己放在其中的密钥库和导出文件。

早期安装可能留下 Python 启动期间生成的缓存。安装器兼容旧版 `runtime/Lib/**/__pycache__` 中大小受限、文件头有效且对应源码列于已验证清单的 CPython 3.12 缓存。这些缓存仍视为不可信内容，仅保留在旧程序备份中，安装器不会执行，也不会带入新版运行目录。其他未知文件仍会阻止升级，新安装包的完整性检查保持严格。

先构建便携 ZIP，再运行 `python -I -S build_installer.py`；也可用 `build_installer.cmd` 完成两步。构建器会在隔离目录验证真实安装、原目录升级、个人数据字节不变、快捷方式替换及拒绝其他软件目录；编译后的专项测试覆盖回滚、中断恢复、运行中进程保护及保留其他快捷方式。验证时不创建真实桌面快捷方式。安装程序没有数字签名，第三方许可发布限制与便携包相同。

构建器会打印最终安装包路径。如果旧的 `dist/offline-key-vault-setup.exe` 仍被打开，新验证通过的安装包会另存为带摘要后缀的文件，旧文件保持不变，请使用构建输出显示的新路径。

公开标准安装包**不捆绑 PyKCS11**。使用硬件令牌时，先从可信离线 wheel 准备锁定依赖，再运行 `python -I -S build_portable.py --with-pkcs11` 构建本地令牌版本；生成独立的 `-local-pkcs11.zip`，其 GPL 分发义务需另行处理后才能对外分享。不要直接把依赖复制到标准版安装目录，完整性检查会拒绝额外文件。应用不会联网下载依赖。

设置提供密钥库保存/打开、密钥导入、密钥导出三个默认目录。输入路径后短暂防抖自动刷新本地目录列表，无需点击“转到”；提交时也按最新输入路径解析。口令/PIN 输入默认隐藏，通过输入框内的小眼睛切换；焦点离开输入框及眼睛控件后重新隐藏。鼠标滚轮作用于指针下的列表、文本或外层表单。

主操作使用红色，普通按钮使用轻量浅灰圆角，危险操作使用浅红提示；输入框、焦点和滚动条样式统一，安装向导采用同一配色。界面说明和长名称会按可用宽度换行；窗口调整时文字、组件、图标和间距一起等比例缩放；窗口内容区保持初始宽高比例，不再通过留白补齐。只允许拖动四个角等比例缩放，禁用四边单向拉伸和最大化，最小缩放比例 80%；主界面正文与导航使用 12 pt、最小字号 10 pt，密集工具表单的最小字号仍为 8 pt。侧栏底部信息和详情操作区利用窗口可用高度排列。窄窗口的双列表单自动改为单列。操作按钮保持在滚动表单之外，滚动条仅在内容溢出时出现，默认路径采用同行选择按钮，硬件令牌按连接、公钥和生成分组，键盘焦点会带动表单显示对应输入框。布局回归检查覆盖 100%、150%、200% Tk 字体缩放；Mac 原生 CI 覆盖 Tk 交互；Retina、触控板及全部显示缩放仍需人工验收。

锁定页的「密钥文本转文件」同时接受公钥和私钥。标准私钥输出默认加密，明文/原始输出需明确允许。`Original` 校验后保留输入字节及原有加密状态，不会添加新的文件口令。

单记录导入会将原始输入字节一起存入认证加密库。「导出导入原文」重新验证主口令后，恢复包含换行及原加密状态在内的原始字节。普通导出保留密钥本身，但编码或加密密文可能改变。旧记录和多记录容器没有保存原文，无法倒推；如需精确还原，请重新导入原始的单记录文档。含导入原文的记录需要本版或更新版本，升级前请备份，不要再用旧版打开这些库。

「查看密钥内容」直接显示库内公钥。显示规范化的明文私钥需再次验证主口令，60 秒后隐藏，锁库立即关闭。程序不自动复制，但用户可以选择/复制明确显示的内容，其他软件也可能截取屏幕。

## 基本使用

1. 在非同步的本地目录创建库，设置至少 12 字符的高强度主口令。长度达标不等于口令难以猜测。
2. 生成或导入密钥，填写名称、标签、备注，由程序保存到加密库。
3. 导出选中的公钥；导出其对应私钥时重新验证主口令。加密私钥导出需另设文件口令。
4. 配对校验时提供公私钥，加密私钥还需填写该文件的导出口令。解析/解密失败表示尚未判定匹配性，不等于两把密钥不匹配。校验结束清空私钥输入和口令。
5. 将加密备份保存在独立离线介质。历史备份保留当时的口令及恢复设置。

配对比较实际公钥参数。两个 OpenPGP 输入比较主密钥及完整子密钥集合；OpenPGP 跨普通格式只比较主密钥。证书用于提取公钥，不作信任判断。普通指纹为 SPKI DER 的 SHA-256，与 SSH wire encoding 的指纹不同。

## 加密文件仍可读取和复制

文本编辑器可以显示加密 PEM 的头尾和 Base64 密文。复制文字得到的仍是加密副本，还需原口令才能恢复私钥。修改扩展名或删除头部的 `ENCRYPTED` 不会解密。

本工具导出的 PKCS#8 PEM 中，`BEGIN ENCRYPTED PRIVATE KEY` 表示加密，`BEGIN PRIVATE KEY` 表示明文。其他格式的标识不同，不能一律仅凭第一行判断加密状态。

**选择明文导出时会清空并禁用导出口令输入框。** 界面再次确认后生成明文文件。JWK、原始私钥及本工具的传统 PKCS#1/SEC1 私钥导出均需该选项。导出文件必须单独保护；修改库主口令不能保护或撤销旧导出副本。

## 连续失败保护与恢复

两项功能均需解锁后配置。自毁默认关闭，启用需明确确认并设置 5–100 次连续认证失败阈值；达到阈值会用销毁标记替换当前库，移除两个凭据封装。

恢复需要提前配置并分开保存的**恢复口令 + 独立恢复文件**。恢复设置新的主口令，不显示原口令。这是双因素恢复，不是每次日常解锁的双因素认证。

保存安全设置会把 OKV1 库升级到 OKV2，旧版本应用无法打开。自毁仅从当前受管理文件中逻辑移除内容，不能安全擦除 SSD 历史块、备份、快照或导出文件。拥有文件系统访问权限的人可以复制/回滚库或离线攻击副本，失败计数不能阻止这些行为。能连续提交错误口令的人也可故意触发自毁。详见 [SECURITY_RECOVERY.md](SECURITY_RECOVERY.md)。

## 安全与隐私

- 全库 AES-256-GCM，使用随机盐、nonce 及固定参数 scrypt。加密 PKCS#8 导出使用 600000 次 PBKDF2-HMAC-SHA256 和 AES-256-CBC；导出格式本身不具备主库的 GCM 认证能力。
- 导入最多 128 KiB，库最多 16 MiB / 1000 条记录；在进入昂贵运算前限制 KDF 计算量及内存参数。
- Windows 新建敏感文件使用受保护的当前用户 DACL，并检查本地卷、链接及路径。不支持持久 ACL 的目标会被拒绝。macOS 检查本地卷，新建敏感文件在写入前移除继承 ACL 并设置 0600。POSIX 路径竞态边界及待完成的人工验收见 MACOS.md。
- 应用不记录私钥、口令或 PIN，不自动复制到剪贴板；不能全面控制 Python/Tcl/OpenSSL 内存副本、已入侵系统、管理员或其他进程。
- 可选的密钥库、导入及导出默认目录仅保存在 `.offline-key-vault-preferences.json` 中，文件受当前用户权限保护。路径和导出名称可能暴露个人或业务信息，即使密钥正文加密。在设置中清空相应目录即可恢复默认；自动读取旧版仅含导出目录的设置。
- 应用没有上传或遥测功能。Python 审计钩子阻止其覆盖的网络/外部进程调用，但不能隔离原生代码或阻止独立云同步软件。严格离线需断网设备或独立实施的操作系统隔离。
- PKCS#11 驱动是本机可执行代码，只应选择可信驱动；摘要本身不认证发布者。Windows 在校验和加载期间持有驱动与父目录句柄，阻止文件替换；macOS 同等强制锁定和实物验证仍待完成。

中英文问题报告说明见 [SECURITY.md](SECURITY.md)。不要在 issue 或支持请求中发送真实密钥、库、恢复文件、口令、个人路径或敏感截图。


测试在 `test-results/` 中生成合成密钥，禁止使用真实密钥作为测试夹具。源码 ZIP 和 SHA-256 文件写入 `dist/`，仅按 `tools/release_manifest.json` 的明确清单打包，不压缩整个工作目录。

发布前：

1. 核对文档、变更和依赖许可；运行本地测试，涉及便携包时验证实际解压包。
2. 将密钥库、恢复文件、导出内容、偏好设置、截图、日志、缓存、依赖及构建/测试输出排除出公开源码。忽略规则和源码白名单共同执行这些排除。
3. 在本地 Git 仓库运行 `python -I -S tools/release.py stage`，再运行 `python -I -S tools/release.py audit --index` 和 `git diff --cached --check`，人工复核暂存内容及已有历史。
4. commit/push 或上传前确认精确目标及明确发布授权。工具不会提交、配置远程或上传。

推送和 PR 的基础 CI 检查源码隐私模式、暂存索引白名单及 Python 语法。单独手动启动的 macOS 工作流还在两个原生架构上构建 DMG、运行密码学/GUI 回归及实际安装自检，通过后生成待审核附件；公开 Release 另行发布。模式扫描不能证明不存在所有类型的秘密。具体发布流程见 [RELEASING.md](RELEASING.md)。
